## 2. ボーダーコリジョン・スナップ・追随ポップアップ詳細仕様

### 2.1 バルーン (Balloon) のボーダーコリジョン仕様

バルーンウィンドウ（`balloon_window_*`）の配置および移動においては、**縦方向（`Y`）を厳格にワークスペース内へ収めつつ、横方向（`X`）は一切制限しない**という非対称な境界ルールを適用する。

#### 縦方向 (`Y`)：絶対クランプ

- 基準範囲はタスクバー抜きのワークスペース縦領域 `[work_y, work_y + work_h]` とする。
- バルーン高さ `height` に対して、ウィンドウ上端 `y` を以下の範囲へ必ずクランプする（`clamp_logical_position_y_only` / `clamp_physical_position_y_only`）。
  - 通常時（`height < work_h`）: `[work_y, work_y + work_h - height]` の範囲内に収める。
  - 例外時（`height >= work_h`、または `work_h <= 0`・非有限値）: 下端がはみ出しても上端が見切れないよう、上端 `work_y` に固定する。

#### 横方向 (`X`)：制限なし

- ワークスペース左右端（`work_x` / `work_x + work_w`）およびモニター外への配置・はみ出し・ドラッグ移動を許可する。
- 水平方向の境界クランプ処理は一切行わない。
- 補足: オフセット未保存の初回デフォルト位置算出（`compute_default_logical_balloon_pos` / `compute_default_balloon_offset`）では、メインキャラ（`scope_id == 0`）の右隣に配置するとワークスペース右端からはみ出す場合に限りキャラ左側へ自動反転配置する。これは初期向きの自動選択であり、明示座標・保存済みオフセット・ドラッグ後の X 座標をクランプするものではない。

#### 全経路への一貫適用

上記の「Y軸のみ `work_area` 絶対クランプ、X軸無制限」ルールは、以下の全経路に漏れなく適用する。

1. **初期表示・再表示 (`show_balloon_window`)**:
   - 明示座標（`x`, `y`）指定時、保存済みオフセット（`AppState::balloon_offsets`）適用時、未保存デフォルト位置算出時、および既に可視状態のバルーン再表示時の縦方向はみ出しチェック（`needs_vertical_clamp`）のすべてで Y 軸のみをクランプし、X 軸は無制限とする。
2. **リサイズ (`resize_balloon_window`)**:
   - バルーンサイズ変更後、新しい `height` によって縦方向がワークスペース上下からはみ出す場合（`needs_vertical_clamp`）のみ Y 座標をワークスペース内へ補正し、現在の X 座標（`pos.x`）はそのまま維持する。
3. **キャラクター追従同期 (`sync_balloon_position_impl` / `sync_balloon_position` / `sync_character_balloon`)**:
   - キャラクター移動・倍率変更・位置リセットに連動してバルーン位置を再計算する際、算出座標 `(char_pos.x + offset.0, char_pos.y + offset.1)` に対して `clamp_physical_position_y_only` を適用する。
4. **ドラッグ後のオフセット保存 (`save_balloon_offset_from_position`)**:
   - ドラッグ終了時、`compute_saved_offset_and_clamped_y` によってバルーンの Y 座標をワークスペース範囲内へ厳格クランプする。
   - Y 座標が補正された場合は即座にバルーンウィンドウを `(balloon_pos.x, clamped_y)` へ再配置した上で、キャラクター基準の相対オフセット `(balloon_pos.x - char_pos.x, clamped_y - char_pos.y)` を保存する。X 方向のオフセットはクランプせずそのまま保存する。

### 2.2 バルーンのタイトルバーレス追随ポップアップ仕様 (`#coord-popup`)

バルーンウィンドウのドラッグ移動中（`balloon-dont-move` が無効な場合）は、ウィンドウ上部の追随ポップアップ（`#coord-popup`）にキャラクター基準の相対オフセットとリセットショートカットの案内を 2 行構成で表示する。

#### 表示条件とライフサイクル

- 左マウスドラッグ（`mousedown` 〜 `mousemove` / `mouseup`）および 1 本指タッチドラッグ（`touchstart` 〜 `touchend`）中に表示する。
- ネイティブウィンドウドラッグ（`startDraggingWindow()`）と並行して 50ms 間隔のポーリング（`startCoordInterval`）を行い、現在位置からリアルタイムに更新する。
- ドラッグ終了時にポップアップを非表示化し、`save_balloon_offset_from_position` を実行する。

#### 2行構成フォーマット

- **1行目 (`.coord-popup-line`)**: `Offset: <x>,<y>`（例: `Offset: -84,80`）
  - 当該バルーンが属するキャラクターウィンドウ（`subchar_window_<scopeId>`）の `outerPosition()` を基準とした相対オフセット整数値（`Math.round(balloonPos.x - charPos.x)` / `Math.round(balloonPos.y - charPos.y)`）を表示する。
  - キャラクターウィンドウ位置を取得できない環境やフォールバック時は、ドラッグ開始位置からの移動差分を表示する。
- **2行目 (`.coord-popup-hint`)**: `Reset: Ctrl+Shift+F10`
  - ヒント行として小さめの文字・透過スタイル（`font-size: 10px; opacity: 0.8`）で表示する。

表示例:

```text
Offset: -84,80
Reset: Ctrl+Shift+F10
```

#### 安全な描画と CSS レイアウト

- 文字列結合による HTML 挿入は行わず、`document.createElement("div")` と `textContent`（`replaceChildren` / `appendChild`）を用いて 2 行を安全に描画する。
- `.coord-popup` は `width: max-content; max-width: calc(100% - 8px); white-space: normal; line-height: 1.3; text-align: center; padding: 3px 8px;` とし、各行（`.coord-popup-line`, `.coord-popup-hint`）でオーバーフロー省略を制御して 2 行が崩れずに収まるようにする。

### 2.3 シェル (Character / Ghost) のボーダー無制限仕様

シェル（メインキャラクターおよびサブキャラクター：`subchar_window_*`）ウィンドウは、**縦方向（`Y`）・横方向（`X`）ともに移動および配置の境界制限を設けない**。

- `show_character_window` / `show_subchar_window` による位置指定、表示中ウィンドウのサイズ変更、ならびにドラッグおよびスナップ確定移動において、X・Y いずれの軸もクランプしない。
- OS タスクバー領域上、ワークスペース外、モニター境界外への部分的または完全なはみ出し配置・移動を許可する。
- `scale_balloon.rs`（`set_character_scale` / `sync_character_balloon`）による倍率変更やバルーン同期でも、キャラクター自身の座標をクランプしない。
- **例外（初期配置とリセットのみ）**: 座標未指定での初回表示および位置リセット（`Ctrl+Shift+F12` / `reset_character_positions`）時に限り、画面外見失いを防ぐためタスクバー抜きのワークスペース（`work_area`）を基準として初期位置を算出する。

### 2.4 シェルのスナップシステム仕様

シェルのドラッグ操作時は、デスクトップ上の配置揃えを支援するためにウィンドウ端スナップシステム（`calculateWindowSnap`）が動作する。

#### 基本パラメータと動作条件

- **スナップ閾値**: 論理 `12px` 基準（`SNAP_THRESHOLD_LOGICAL_PX = 12`）。デスクトップ環境では対象モニターの `scaleFactor` を乗じた物理閾値 `Math.max(1, Math.round(12 * workArea.scaleFactor))` を使用する。距離が閾値厳密未満（`< snapThreshold`）のとき吸着対象とみなす。
- **`Ctrl` キー押下による一時無効化**: ドラッグ中に `Ctrl` キーが押下されている間（`keydown` / `keyup` / `blur` / ポインタイベント `ctrlKey` で同期）はスナップ判定をスキップし、両軸とも `"None"` として現在座標をそのまま保持する。
- **X軸・Y軸独立判定**: X軸とY軸は互いに独立してスナップ判定を行う（例: X軸のみ `Character`、Y軸のみ `Monitor`、または片軸のみスナップ）。

#### スナップ対象種別と判定優先順位

各軸において未吸着（`"None"`）の状態で、以下の順序で吸着先を判定する。

1. **`Initial`（初期配置・基準位置座標）**:
   - 当該キャラクターの初回表示座標または直近の位置リセット（`reset_character_positions` / `character-positions-reset`）で記録された基準座標 `initialPos`（`x`, `y`）に対し、`|current - initial| < snapThreshold` を満たす場合に `Initial` へ吸着する。
2. **`Monitor`（タスクバー抜きワークスペース端）**:
   - モニター全体ではなく、現在ウィンドウに対応するタスクバー抜きのワークスペース `workArea`（`x`, `y`, `width`, `height`）の上下左右端のうち最も近い辺へ吸着する。
   - X軸候補: ワークスペース左端 `work_x`、ワークスペース右端 `work_x + work_w - winWidth`
   - Y軸候補: ワークスペース上端 `work_y`、ワークスペース下端 `work_y + work_h - winHeight`
3. **`Character`（他キャラクターウィンドウ端）**:
   - 自ウィンドウおよびバルーンウィンドウ（`balloon_window_*`）を除く、現在可視状態（`isVisible() === true`）の他キャラクターウィンドウ（`subchar_window_*`）の上下左右端のうち最も近い候補へ吸着する。
   - X軸候補: 相手の右端に左端を隣接（`other.x + other.width`）、相手の左端に右端を隣接（`other.x - winWidth`）、左端揃え（`other.x`）、右端揃え（`other.x + other.width - winWidth`）
   - Y軸候補: 上端揃え（`other.y`）、下端揃え（`other.y + other.height - winHeight`）、相手の下端に上端を隣接（`other.y + other.height`）、相手の上端に下端を隣接（`other.y - winHeight`）

#### デスクトップドラッグ統合と確定適用

- Tauri デスクトップ環境では、ドラッグ開始時に OS ネイティブの `startDraggingWindow()` を使って滑らかにウィンドウを移動させつつ、50ms ポーリング（`startCoordInterval`）および `mousemove` / `keydown` / `keyup` ごとに現在位置に対して `calculateWindowSnap` を評価し、スナップ予測位置・スナップ種別を `#coord-popup` に反映する。
- ドロップ時（`mouseup` / `touchend`）に `Ctrl` が押下されておらず、かつ X または Y のいずれかにスナップが発生している場合、`commitSnapOnDragEnd` が `show_subchar_window`（および `sync_character_balloon`）を実行してスナップ先座標へ確定移動する。
- 非 Tauri 環境（ブラウザプレビュー等）では、ドラッグ中にスナップ後座標との差分を `moveCurrentWindowBy` へ直接適用する。

### 2.5 シェルのタイトルバーレス追随ポップアップ仕様 (`#coord-popup`)

シェルのドラッグ移動中は、ウィンドウ上部の `#coord-popup` に現在座標（スナップ予測座標）・有効なスナップ種別・`Ctrl` 無効化ヒントを 2 行構成で表示する。

#### 2行構成フォーマット (`formatSnapTooltipText`)

- **1行目**: 整数丸め座標 `<x>,<y>` に続けて、**スナップが発生した軸のみ**を括弧内で表示する。`"None"`（未スナップ）の軸は省略し、両軸とも `"None"` の場合は括弧自体を出力しない。
- **2行目**: `Press Ctrl to disable`（`showCtrlHint: true` 時）

| スナップ状態                         | 1行目の出力例                               | 2行目の出力例           |
| :----------------------------------- | :------------------------------------------ | :---------------------- |
| X軸のみ `Character` に吸着           | `1363,842 (Snap X:Character)`               | `Press Ctrl to disable` |
| Y軸のみ `Monitor` に吸着             | `1363,842 (Snap Y:Monitor)`                 | `Press Ctrl to disable` |
| X=`Monitor`, Y=`Initial` に吸着      | `1363,842 (Snap X:Monitor, Snap Y:Initial)` | `Press Ctrl to disable` |
| スナップなし（または `Ctrl` 押下中） | `1363,842`                                  | `Press Ctrl to disable` |

表示例:

```text
1363,842 (Snap X:Character)
Press Ctrl to disable
```

```text
1363,842 (Snap Y:Monitor)
Press Ctrl to disable
```

```text
1363,842 (Snap X:Monitor, Snap Y:Initial)
Press Ctrl to disable
```

```text
1363,842
Press Ctrl to disable
```

#### 安全な描画と CSS レイアウト

- `formatSnapTooltipText` は HTML タグを含まない `\n` 区切りのプレーンテキストを返し、`character.ts` で `coordPopupEl.textContent` へ代入する。
- `.coord-popup`（`ui/css/character.css`）では `width: max-content; max-width: calc(100% - 8px); overflow-wrap: break-word; padding: 3px 6px; font-size: 11px; line-height: 1.3; text-align: center; white-space: pre-line;` を指定し、横方向クリップを起こさず 2 行を中央揃えで表示する。
