# 厳密コード検証システム規定 (Strict Code Verification Protocol)

## 概要

Nanai Android Mascot プロジェクトにおける開発ドキュメント、マニュアル規格、適合確認インデックス (`docs/` 配下) の記述において、**「実際のソースコード実装および自動テスト結果と 1 対 1 で100%厳密に一致する状態」**を維持・運用するためのプロジェクト規定である。

---

## 核心原則 (Core Principles)

### 1. 1 対 1 対比と個別ファイル整合性の原則 (1-to-1 Exact Traceability)
- インデックスファイル (`index.md` や 総合マトリクス) に記録する対応状況 (`✅ 対応済`, `⚠️ 部分対応`, `❌ 検出なし`) は、**対応する個別の仕様ファイル (`*.md`) 内の突合・検証結果と 100% 厳密に一致しなければならない**。
- 個別ファイルにおいて `❌ 検出なし` や `未確認` となっている項目を、インデックスやサマリー側で誤って `✅ 対応済` と表記することは厳重に禁止する。

### 2. ソースコード直接検証の原則 (Source Code Line Traceability)
- `✅ 対応済` と表記するためには、実際のソースコードファイル (`src-tauri/` または `ui/js/`) 内の関数名・変数名・キーバインド処理の該当行番号を個別ファイルに明記しなければならない。
- 例:
  ```markdown
  ## 実装箇所
  - `ui/js/core/actions/balloon-descript/font.js` `props["font.outline"] === "1"`
  ```

### 3. 自動テスト通過の必須義務 (Automated Test Validation)
- 仕様項目を `✅ 対応済` と認定するには、対応する単体テスト（Vitest テストケース）が存在し、エラーゼロで正常通過 (PASS) していることを要条件とする。

---

## 運用・維持手順 (Operational Workflow)

1. **仕様追加・修正時**:
   1. ソースコード (`src-tauri/` または `ui/js/`) を実装・修正する。
   2. 対応する Vitest 単体テスト (`tests/*.test.js`) を作成・更新し、`npx vitest run` を実行して全件 PASS を確認する。
   3. 対応する個別の仕様ファイル (`docs/spec/ukadoc-spec/.../*.md`) の「対応状況」「突合結果」「実装箇所」を更新する。
   4. インデックスファイル (`index.md` / `SUMMARY.md`) の該当行を個別ファイルと一致するように更新する。

2. **定期監査時**:
   - `grep` 等を用いて個別ファイル内の「対応状況」と `index.md` 内の表記に食い違いがないか走査し、不一致が存在する場合は即座に個別ファイルの現実に合わせて修正する。
