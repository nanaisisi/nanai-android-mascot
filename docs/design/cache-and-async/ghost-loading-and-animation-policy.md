# ゴースト読み込み・会話表示・サーフィス描画の負荷対策コンセプト

## 目的と境界

「処理中」バナーが出ている間に会話を始めないことと、長時間の会話・アニメーションで処理が積み上がらないことを両立する。**会話を遅らせて負荷を隠すのではなく、繰り返し発生する仕事と非同期処理の競合を減らす**。この文書は現行の実装方針を説明するもので、Windows 実機での CPU・メモリ・IPC 計測による効果の確定や、特定コミットを性能悪化の発端と認定するものではない。

## 1. 読み込みは並列、会話開始には明確なゲート

`GhostController.selectGhost()` はバナー表示、`surfaces.txt` の読み込み、初期キャラクター画像の準備を開始する。SHIORI の `load_ghost` も並行して実行する。これらがすべて終わり、`hide_loading_banner_window` の完了を待ってから `OnBoot` を送信し、その後に定期イベントタイマーを開始する。`autoLoadGhost()` と初回ゴースト選択側もこの準備完了を待つ。対象は `ui/js/ghost/ghost.js`、`ui/js/ghost/ghost-shiori.js`、`ui/main.js`。

```text
ゴースト選択
  ├─ バナーを表示 ─────────────┐
  ├─ surfaces.txt と初期画像 ─┤ すべて完了
  └─ SHIORI をロード ──────────┘
                  → バナー非表示完了 → OnBoot → 定期イベント
```

ゴーストを連続して切り替えたときは世代番号を照合し、古い読み込みの完了が新しいゴーストのバナーを閉じたり `OnBoot` を発行したりしない。バナー表示に失敗した場合は警告を出して読み込みを継続する（表示できないバナーを永久に待たない）。**ウィンドウ表示コマンドの完了と WebView の初回描画完了は同義ではない**ため、バナーが実際に何フレーム見えたかまでは保証していない。

## 2. 描画更新と状態変更を分離

通常の `updateSurface(surfaceId, scopeId)` はサーフィス番号を設定し、アニメーションのスケジュールを更新する。一方、SERIKO のフレーム描画と終了時のベース画像への復帰では `updateSurface(baseSurfaceId, scopeId, extraLayers)` を使い、サーフィス番号とスケジュールを変更しない。復帰時は空配列 `[]` を指定する。

これにより「アニメーションが終了する → ベースサーフィスを通常更新する → タイマーを止めて再スケジュールする」という自己増殖する経路を避ける。同じ `scopeId`・ベースサーフィス・アニメーション ID の再生中は多重起動させず、各フレームの画像合成が完了してから次へ進む。これは口パクが各文字から呼ばれる場合にも効く。対象は `ui/js/surface/surface-animation-manager.js` と `ui/js/surface/ghost-surface.js`。

## 3. I/O と表示の順序を制御する

- 同じゴースト・シェル・画像 ID の PNG/PNA は Promise ごとキャッシュし、並行した要求も1回の読み込みに合流する。保持数は最大64エントリ。ゴースト選択時に画像とクロマキーのキャッシュを破棄する。アニメーションフレームではキャラクターウィンドウの再表示コマンドを送らない。
- 合成が遅れた古いフレームは、スコープ別の更新世代を確認してから表示を反映する。後から始まった更新を古い更新が上書きしない。
- 差分レイヤーの画像もベース画像と同様に PNA またはクロマキー処理を通してから合成する（`ui/js/surface/ghost-surface.js`、`ui/js/surface/surface-compositor.js`）。この差分透過処理は別途統合された変更であり、負荷軽減のために省略しない。

## 4. 会話のテンポは遅延によって犠牲にしない

デスクトップバルーンへの同期に使っていた固定の 60 ms 待機をなくす。同一 JavaScript ターン内の連続更新は `queueMicrotask` でまとめるが、次の文字が表示されるまで不必要に送信を保留しない。`ui/js/ghost/sakura-play.js` の1文字ごとの 40 ms は元々の文字送り速度であり、負荷対策用の待機とは区別して残す。さくらスクリプトの明示的な待機・ポーズも変更しない。

## 検証と未確定事項

- `node --test tests/*.test.js`: バナーと `OnBoot` の順序、初回選択の準備待ち、古いロードの無効化、画像読み込みの再利用、描画順序、口パク重複抑止、会話表示の早期同期、差分レイヤーの透過処理を検証する。
- `npx biome lint ui/js/ghost/ghost.js ui/js/ghost/ghost-shiori.js ui/js/ghost/sakura-play.js ui/js/surface/ghost-surface.js ui/js/surface/surface-animation-manager.js` と `npm run build` を実行する。
- 自動テストは Tauri/Windows の実ウィンドウ描画、実際の CPU・メモリ・IPC 件数を測っていない。効果の判定には、同じゴースト・会話・稼働時間で変更前後の CPU、メモリ、アニメーション再生数、IPC 件数、バナー表示順序を実機比較する。`0x80070718` の解消は未確認。

関連する広域の検討事項は [軽量化・IPC安定化計画](performance-and-ipc-stabilization.md) を参照。そこにあるドラッグ最適化や先読みの段階化まで、ここで実装済みとみなさない。
