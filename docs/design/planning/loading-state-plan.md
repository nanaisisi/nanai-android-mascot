# ローディング状態機構 計画

## 目的

画像・アイコン・ネットワーク取得物の読み込みが完了するまで「読込み中」状態を表示し、未完了のまま描画して表示崩れ・ちらつきが出ることを防ぐ。

## 規格上の根拠（ukadoc）

- サーフィス画像: シェルの `surfaces.txt` / `\s[ID]` / `\i[ID]` は画像が揃って初めて表示できる。ロード待ちは規格上は暗黙で、描画前に読込み完了を保証するのが実装側の責務。
- バルーン画像: `\_b[ファイルパス,x,y|inline,オプション]`（`balloon-text/_b-*.md`）。現状は未実装（❌ 検出なし）。実装時に同じ機構へ載せる。
- メニュー画像: オーナードローメニュー定義（`manual/owner-draw-menu.md`）。現状は読込処理なし。
- ヘッドライン等のネットワーク取得物（`ssp/howto/headline.md`）。取得完了まで待機表示が必要。
- 規格にローディング表示そのものの明示仕様は見つからなかった。独自拡張として扱い、規格動作（完了後の表示結果）は変えない。

## 設計

### 共通ローディング状態

- 状態: `idle` / `loading` / `ready` / `error`。
- 対象単位ごと（サーフィス、メニュー、バルーン、ヘッドライン）に状態を持つ。
- 読込み完了イベントで `ready` へ遷移し、そこで初めて描画する。
- 失敗時は `error`。タイムアウトとリトライ上限を設ける。

### 実行開始ゲート（会話・スクリプト開始タイミング）

- 会話などの実行開始は、ローディング完了（`ready`）を起点にする。
- 起動時: 初期サーフィスとバルーンが `ready` になってから `OnBoot` / `OnFirstBoot` / `OnGhostChanged` 等の SHIORI イベントを発行し、返ってきたスクリプトの再生を開始する。
- 再生中: `\s` / `\i` / `\_b` の対象画像が `ready` になるまで、スクリプト進行を一時停止する。
- 必須アセットがタイムアウトした場合は `error` として扱い、劣化表示（プレースホルダ）で再生を開始するか中止するかを設定で選べるようにする。
- SHIORI への問い合わせ自体は並行してよいが、表示と再生の開始はゲートが開いてからにする。

### 画像プリロード

1. 描画に必要な画像 URL を列挙する（サーフィス合成要素、メニュー画像、`\_b` 画像）。
2. `Image.decode()` を `Promise.all` でまとめて待つ。
3. 完了まで前の表示を維持するか、ローディング表示を出す。
4. 既存のキャッシュ設計（`docs/design/cache-and-async`）と統合して二重取得を避ける。

### 表示

- ゴースト/サーフィス: 初回は読込み中のスピナー、またはプレースホルダを表示。切替時は旧表示を維持する。
- メニュー: 画像が揃うまで項目を非活性にするか、スケルトンを表示する。
- バルーン内画像: 読込み完了までスペースを確保し、レイアウトのずれを防ぐ。
- ヘッドライン: 「取得中…」を表示し、失敗時は再試行の導線を出す。

### SakuraScript との整合

- `\_b` / `\i` / `\s` の実行は、必要な画像の `ready` を待ってから次のスクリプト処理へ進める。
- `\w` / `\_w` 等のウェイトとは別枠で、ロード待ちはスクリプト進行を一時停止する。

## 実装ステップ

1. 現行の画像取得・描画経路を調査する（サーフィス、メニュー iframe、バルーン）。
2. ローディング状態の共通モジュール（状態・イベント・タイムアウト）を作る。
3. サーフィス描画へ適用する。
4. メニュー（`ui/menu-iframe.html`）へ適用する。
5. ヘッドライン取得へ適用する。
6. `\_b` 実装時に共通機構へ載せる。
7. 通信遅延・失敗の模擬テストを追加する。
